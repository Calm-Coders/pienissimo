## 🟢 The order-level link is dynamic, and it is re-sent

Elena Spini's overnight doubt was the single link per order: _"se gliela facciamo
vedere a Fabrizio impazzisce."_ Aurel Mrruku's answer is that the link is
generated once at order level and **the same link is re-sent in each campaign
communication**; one order can carry several campaigns with different
communication dates, but the URL does not change. His analogy: _"è come quando
compri su Amazon … puoi comprare 10 prodotti di cui due sono stati già spediti e
due vengono spediti dopo n mesi."_ Elena Spini accepted it.

## 🟢 Elena Spini withdrew her own 30/09 objection

On whether one tranche can unlock assets for several different events:

> _"non succede che in una tranche ci sono più eventi. In realtà questa è una
> grande cazzata. Nella tranche ci possono essere più eventi."_

She had argued the opposite the day before. Aurel Mrruku: _"Non mi credevi ieri."_
The multi-event tranche is now the written premise of the whole aggregation rule.

## 🔑 `Rinuncia` is per edition — third granularity in three days

> proprio il child, il figlio edizione e ti metto rinuncia su quello."_

## 🔑 The three fields got their names

| Field | Purpose | Set by |
| --- | --- | --- |
| `Ready_for_Ticket_Dispatch__c` | Checkbox, `TRUE` on confirmation of a participant | Salesforce |
| `Ticket_Sent__c` | Checkbox, `TRUE` after the send | Marketing Cloud write-back |
| `Ticket_Sent_Date__c` | Date/time of the send | Marketing Cloud write-back |

The Marketing Cloud selection query is
`Ready_for_Ticket_Dispatch__c = TRUE AND Ticket_Sent__c = FALSE`.

🔴 **Which object carries the flag was left open in the room.** The document says
_"Oggetto per il Flag: Asset ? da confermare con Aurel"_, and Aurel Mrruku in the
call: _"Può essere su campaign, può essere su asset."_ Elena Spini: _"esatto da
capire."_ The fields were built that same evening across **two** objects —
→ [OI-199](../items/OI-199%20The%20ticket%20send%20flag%20fields%20are%20split%20across%20Asset%20and%20Order.md).

Aurel Mrruku chose the date field over field history: _"se mettiamo la history sul
ticket sent, vediamo quando è diventato true … meglio che mettiamo ticket sent
date."_

## 🔑 A file-naming contract for the ticket PDF

So Marketing Cloud can pick the right attachment off the Asset, the ticket file
must be named on a fixed prefix — Aurel Mrruku: _"anche sul biglietto decidiamo un
nome del file, lo chiamiamo biglietto … lui deve andare a pescare il file che
inizia con biglietto."_ Elena Spini: _"Yes. Esatto."_

⚠ **This is a build constraint nobody has written into a requirement.** The asset
can carry more than one document — the QR ticket and the participation document of
[OI-194](../items/OI-194%20The%20ticket%20is%20a%20signed%20participation%20document%20not%20just%20a%20QR%20code.md)
— and the send picks by filename prefix.

## 🟢 Page layout settled

Tickets still to be named go **at the top, grouped by edition**; tickets already
named or assigned for the same order go **at the bottom of the same page**. Elena
Spini wanted tabs; Aurel Mrruku's single scrolling page won.

## Order state when there are no tranches

Worked out live, with both of them unsure: `Fatturato` is the state when an order
carries several tranches, `Incassato` when the last one settles or when a single
invoice is paid. The document records **`Incassato`** as the trigger for
`Disponibile` on an order without tranches.
→ [OI-74](../items/OI-74%20Asset%20state%20machine.md)
